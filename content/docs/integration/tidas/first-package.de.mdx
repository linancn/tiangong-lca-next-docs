---
title: "Das erste Paket prüfen und konvertieren"
description: "Eine Übungsdatei validieren, in eILCD konvertieren, zurückwandeln und die Aussagekraft der Berichte verstehen."
---

Sie konvertieren eine vollständige Flow-JSON-Datei in eILCD XML, wandeln sie zurück und prüfen erneut. [Installieren Sie zuerst tidas](/de/docs/integration/tidas/installation/) und bestätigen Sie `tidas 0.2.1` mit `tidas --version`. Führen Sie alles im selben neuen Übungsordner aus.

## 1. Übungsdatei herunterladen

Führen Sie diese beiden Befehle am gewünschten Speicherort aus. Sie gelten für macOS/Linux und PowerShell 7; bei vorhandenem Verzeichnis einen neuen Namen wählen. Alle weiteren relativen Pfade beginnen in diesem Übungsordner.

```bash
mkdir tidas-practice
cd tidas-practice
```

Speichern Sie die [Flow-Übungsdatei](/assets/docs/tool-guides-v1/demo-flow.json) unter `sample/flows/demo-flow.json`. `flows` ist das Typverzeichnis; legen Sie die JSON-Datei nicht direkt in die Paketwurzel. Erstellen Sie Ordner und Datei im Dateimanager oder mit diesen Befehlen.

macOS / Linux:

```bash
mkdir -p sample/flows
curl --proto '=https' --tlsv1.2 -fsSL https://docs.tiangong.earth/assets/docs/tool-guides-v1/demo-flow.json -o sample/flows/demo-flow.json
```

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force sample/flows
Invoke-WebRequest https://docs.tiangong.earth/assets/docs/tool-guides-v1/demo-flow.json -OutFile sample/flows/demo-flow.json
```

Alle UUIDs und Referenzen sind fiktiv. Die Datei zeigt Strukturprüfung und Konvertierung, kein vollständiges produktives Abhängigkeitspaket. Nicht hochladen, veröffentlichen oder für Berechnungen verwenden.

## 2. TIDAS JSON prüfen

Befehle einzeln ausführen. Direkt danach zeigt `echo $?` unter macOS/Linux beziehungsweise `$LASTEXITCODE` in PowerShell 7 den Exit-Code; spätere Befehle können ihn ersetzen. Außer bei ausdrücklich erwarteten Anmelde-/Fehlerbeispielen bei einem Wert ungleich null anhalten und den Fehler zuerst beheben.

| Terminal | Exit-Code sofort abfragen |
| --- | --- |
| macOS / Linux | `echo $?` |
| PowerShell 7 | `$LASTEXITCODE` |

```bash
tidas validate sample --input-format tidas-json --format json
```

Erfolg bedeutet Exit-Code `0`, `status: succeeded` und `exit_class: success`. Prüfen Sie anhand dieser Felder, dass ein Dokument statt eines leeren Ordners validiert wurde:

| Feld | Erwartung im Beispiel |
| --- | --- |
| `summary.validation.document_count` | `1` |
| `summary.validation.error_count` | `0` |
| `summary.eilcd_projection_validation.ok` | `true`: eILCD-Projektion besteht die XSD-Prüfung |
| `summary.semantic_roundtrip.ok` | `true`: Die Quellsemantik lässt sich wiederherstellen |

## 3. In eILCD konvertieren und Ausgabe prüfen

Behalten Sie das Präfix `./` im Ausgabepfad bei und wählen Sie ein noch nicht vorhandenes Verzeichnis. Ein- und Ausgabe dürfen sich nicht überschneiden. Die Daten liegen unter `converted/data/`, nicht direkt unter `converted/`. Zugehörige Schemas werden ebenfalls ausgegeben.

```bash
tidas convert sample --output ./converted --to ilcd --format json
```

```bash
tidas validate converted/data --input-format ilcd-xml --format json
```

Im Konvertierungsbericht wird `summary.conversion.converted_file_count: 1` erwartet. Die zweite Prüfung muss `summary.validation.document_count: 1` und `error_count: 0` ergeben. Erzeugte Dateien sind nicht automatisch geprüfte Dateien: Kontrollieren Sie beide Befehle.

## 4. Nach TIDAS zurückwandeln und erneut prüfen

```bash
tidas convert converted/data --output ./roundtrip --to tidas --format json
```

```bash
tidas validate roundtrip/data --input-format tidas-json --format json
```

Auch die letzte Prüfung muss `succeeded`, ein Dokument und null Fehler melden. Damit sind Eingabeprüfung, Konvertierung, Ausgabeprüfung und Rückkonvertierung abgeschlossen. Bewahren Sie `sample`, `converted` und `roundtrip` zum Vergleich auf; verwenden Sie beim Wiederholen neue Ausgabeordner.

Für eine Wiederholung am einfachsten einen neuen äußeren Übungsordner mit unveränderten Befehlen verwenden. Wenn Sie nur einen Ausgabeordner umbenennen, müssen alle späteren Prüf-/Konvertierungspfade ebenfalls angepasst werden, damit keine alten Ergebnisse geprüft werden.

## Erfolg und Fehler beurteilen

Erfolg beweist, dass das Dokument die Struktur- und Semantikregeln des Werkzeugs erfüllt, XSD-konformes eILCD erzeugt und die Quellsemantik wiederherstellt. Er beweist weder vorhandene Referenzdatensätze noch vollständige Abhängigkeiten und ersetzt keine wissenschaftliche Prüfung oder Veröffentlichungsfreigabe.

| Symptom | Maßnahme |
| --- | --- |
| Dokumentzahl `0` | Eingabepfad und `flows` prüfen; ein leerer Scan erfüllt die Aufgabe nicht |
| `completed-with-issues`, Exit `2` | Fehlerpfade und Diagnosen lesen, Quelldatei korrigieren und wiederholen |
| `failed`, Exit `74` | Dateien, Schreibrechte und Ausgabepfad prüfen; mit `0.2.1` ausdrückliche Verzeichnispfade wie `./converted` verwenden |
| Ausgabeordner vorhanden | Neuen Ordner wählen, bisherige Eingaben und Ergebnisse nicht überschreiben |

Für vollständige Fehlerlisten, andere Importformate und Skripte siehe [Befehls- und Berichtsreferenz](/de/docs/integration/tidas/reference/).
